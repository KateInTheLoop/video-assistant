CV

The CV is the ground truth: stories are drafted from it and it is sent to Claude with every hint so it can point at your real experience. Upload a file or paste text; either way you get editable plain text here, the most token-efficient form for Claude. DOCX, ODT and text files are read locally and never leave the machine; a PDF is transcribed once by Claude (a few seconds). Old .doc files and Google Docs: download as .docx first.


  
  
  





  
  




Story bank

These are the only things hints will point at. Edit them until they sound like you (edits save as you type). Add stories the CV doesn't show: a failure, a conflict, a time you changed your mind.

About the job



  







  
  


Claude reads the job description against your story bank and lists the questions it makes likely. A ⚠ line is a gap: a probable question with no story behind it. Those are the ones to prepare; during the call a question with no matching story is flagged the same way.

    


    What the coach sees
    
The reusable context sent with live hints, including the response format. Sizes use a rough four-characters-per-token estimate; the model's tokenizer can give a different count. Count with API measures a sample hint with an empty transcript. We request one-hour caching for unchanged context; cache hits depend on the provider. New transcript text, interview history and generated answers are billed separately. See Diagnostics for actual cache reads.

    

    
  
  

    


    Backup and transfer
    
Everything lives only in this browser's extension storage. Export the active candidate or job as a JSON file to move it to another machine or keep a copy; importing adds it as a new entry. The story-bank export is the older format: stories only, merged by title.

  Diagnostics and developer mode
  One row per live hint: latency, model, tokens in and out, and how many input tokens came from the prompt cache. After the first hint of a session the cache share should be high, which is what keeps hints fast and cheap.
  
    
  
    
  
    
  
  Adds trace points to the coach window: every caption, scheduler decision, hint request, first token, partial render and error, with millisecond offsets from the session start. In developer mode they are logged to the coach window's console (right-click the window, Inspect) and Save transcript also downloads a .trace.log next to the transcript. Off by default; it changes nothing about what is sent to Claude.

    


    
  Past sessions
  Each stopped session keeps its transcript, pacing per answer, and a debrief: which story you used, which STAR parts were present, one thing that went well and one to improve. Nothing here is uploaded anywhere.
